# Material terminology

Source: [Glossary](https://m3.material.io/foundations/glossary).

Read [term definitions](references/terms.md) for the terms used in the current task.
The reference summarizes the supplied glossary without importing component specifications from other pages.

## Key distinctions

- A color scheme maps color roles to palette tones. A theme combines several styles and attributes.
- A light scheme is not a light theme. Dark themes can also change elevation and states.
- Dynamic color means the app responds to user-generated color inputs. An algorithmic palette alone does not establish dynamic color.
- A source color initiates derivation. A key color is transformed from that source and forms a tonal palette's basis.
- Reference tokens expose available values. System tokens define roles. Component tokens define component element attributes.
- A token's role describes its purpose. Its value defines the design attribute.
- Guidelines explain usage and behavior. Specifications define annotated values and coded capabilities.
- A condition determines when and how a layout or component adapts.

## Review terminology

Check whether scheme, theme, source color, key color, token type, role, and value retain their distinct meanings.
